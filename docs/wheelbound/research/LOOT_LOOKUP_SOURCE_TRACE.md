## Data origin and request path

The real [plugin](https://github.com/donth77/loot-lookup-plugin/tree/58812e18d0f955d597c4894ece0ae23aff1a3a74) obtains rendered Wiki HTML when a lookup is requested. No shipped monster-drop database or Jagex private drop API appears in the inspected production path. A player enters a name or clicks Lookup Drops; [LootLookupPlugin](https://github.com/donth77/loot-lookup-plugin/blob/58812e18d0f955d597c4894ece0ae23aff1a3a74/src/main/java/com/lootlookup/LootLookupPlugin.java) obtains NPC name/ID/combat level and hands them to [LootLookupPanel](https://github.com/donth77/loot-lookup-plugin/blob/58812e18d0f955d597c4894ece0ae23aff1a3a74/src/main/java/com/lootlookup/views/LootLookupPanel.java). Combat level helps select the display tab; it does not calculate personal receiving probability.

[WikiScraper](https://github.com/donth77/loot-lookup-plugin/blob/58812e18d0f955d597c4894ece0ae23aff1a3a74/src/main/java/com/lootlookup/osrswiki/WikiScraper.java) requests Special:Lookup using NPC identity/name and the injected asynchronous HTTP client. It parses rendered headings and item-drops tables with Jsoup. Rows yield item names, quantities, rarity text/numeric fraction, displayed prices and icon URLs. Specific redirects handle grouped bosses/chests. HTTP/format failure can result in an empty output. Approximation marks,2x/3x prefixes and bracketed annotations can be removed; only the first semicolon-separated rarity feeds the numeric value. No account/group/contribution-rate model is implemented here. No explicit application drop-table cache was found; shared HTTP-client caching configuration was not audited. These findings explain the data flow, not current network success.

[Constants](https://github.com/donth77/loot-lookup-plugin/blob/58812e18d0f955d597c4894ece0ae23aff1a3a74/src/main/java/com/lootlookup/utils/Constants.java) identifies plugin requests using the normal RuneLite user agent plus its loot-lookup suffix. [Util](https://github.com/donth77/loot-lookup-plugin/blob/58812e18d0f955d597c4894ece0ae23aff1a3a74/src/main/java/com/lootlookup/utils/Util.java) separately downloads icons from Wiki URLs with image format headers. Wiki prices are display data, not an eligibility/FP pricing policy.

## Display limitations and verification

[WikiItem](https://github.com/donth77/loot-lookup-plugin/blob/58812e18d0f955d597c4894ece0ae23aff1a3a74/src/main/java/com/lootlookup/osrswiki/WikiItem.java) retains a display rarity string but formats percentages from the numeric field. That field is not a complete conditional/personal probability model. Different source/method contexts and table notes still need independent interpretation. Main items are represented by name/image rather than a validated canonical item-ID acceptance mapping.

[The live canary source](https://github.com/donth77/loot-lookup-plugin/blob/58812e18d0f955d597c4894ece0ae23aff1a3a74/src/test/java/com/lootlookup/osrswiki/WikiStructureLiveTest.java) checks selected page structure/icons and is opt-in; its corpus excludes raid reward pages because the scraper does not support their table representation. We did not execute it or verify its CI results. [The standalone lookup utility](https://github.com/donth77/loot-lookup-plugin/blob/58812e18d0f955d597c4894ece0ae23aff1a3a74/src/test/java/com/lootlookup/WikiScraperTest.java) can run the scraper without the game client; its existence is not a successful run in this session.
